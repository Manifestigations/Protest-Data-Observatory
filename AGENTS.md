# AGENTS.md

Operational map for coding agents. Read this file, then
`src/model/index.ts` → `src/site/routes.ts` → `src/entry/main.ts`.

## Ground truth

- TypeScript, ESM, no framework. Charts: Chart.js on `<canvas>`. Markup: htm
  tagged templates bound to real DOM nodes (`src/core/html.ts`) — no virtual
  DOM, nothing re-renders. One esbuild bundle serves all pages.
- Node ≥ 22.18 (native type stripping). No test runner.
- `docs/` is **committed build output** served by GitHub Pages as-is. No CI
  build, no CI deploy.
- Not verified data: never present a figure as fact in copy or docs.
- Bilingual throughout. `Bi = { en: string; fr: string }`.

## Where the data comes from — read this before touching anything

The figures are authored in **`Manifestigations/Dataset`**. In this repository
`src/data/**` is **not data**: every file there except `src/data/notes.ts` is a
one-line re-export shim into `vendor/dataset/src/data/…`, generated by
`scripts/make-shims.js`. `src/data/notes.ts` is real (note copy, rendered per
locale).

So:

- **Never edit a file under `src/data/` except `notes.ts`.** A correction made
  in a shim is destroyed the next time the shims are regenerated, and it never
  reaches the Dataset repo where the figure is reviewed.
- **Never run `node scripts/make-shims.js` casually.** It rewrites _every_ `.ts`
  under `src/data` with no exclusion list — including `notes.ts`, which is
  hand-written prose. Check `vendor/dataset/src/data/notes.ts` exists first, or
  you will delete the note copy.
- The shims import `vendor/dataset/src/data/<same relative path>`. If that
  directory is missing on your clone, nothing under `src/data` resolves and the
  build fails on the first import. `.gitmodules` is committed; the `vendor/`
  checkout is what supplies the code.
- `src/model/index.ts` is **real** here, not a shim — the types the app is
  written against live in this repository.
- `src/copy/{format,interpolate,markers,types}.ts` are thin re-exports of the
  shared i18n core; `src/copy/{index,lookup,state,meta-overrides,a11y,chrome}.ts`
  are real, site-specific code. Assume a small file (< 250 B) under `src/copy/`
  is a re-export and open the Dataset original before editing.

**The submodule pin is the join.** `src/copy/types.ts` re-exports
`@manifestigations/dataset`, so the `ChargeId` union, `ActRecord`, `Sitting`
and every other data type come from `vendor/dataset` at whatever commit is
pinned. Two consequences: a data merge in `Dataset` is not live here until the
pin moves, and a type error naming a `ChargeId` you cannot find anywhere is a
pin mismatch before it is a copy problem. Check `git submodule status` first.

## Commands

```bash
npm install

npm run build # one-shot production build → docs/bundle.js + docs/styles.css
npm run dev # watch build + spawns server.ts on 127.0.0.1:3000
npm run typecheck # tsc --noEmit — always run
npm run lint # eslint .
npm run format:check # prettier --check .
npm run check:comments  # comment/header conventions
npm run check-baseline
npm run check-size
npm run check-a11y
```

There is **no `npm run dev:server`**. `npm run dev` starts the watcher _and_
the server as a child process (`scripts/build.ts`); to serve `docs/` on its own,
run `node server.ts`.

## Invariants — do not violate

1. **After any change under `src/`, rebuild and stage `docs/bundle.js` and
   `docs/styles.css`.** Never edit those by hand. Sourcemaps are emitted only
   under `--watch` (`sourcemap: dev`, `dev = watch`), so a normal
   `npm run build` produces **no** `.map` files: do not stage
   `docs/bundle.js.map` or `docs/styles.css.map` from a production build —
   they would be stale and would no longer describe the bundle.
2. **`Band = number | [number, number]`.** A published range stays a range.
   Never average two publishers; never midpoint a band in the data layer.
3. **Never change a `Flag` to make a series continuous.** `r|p|e|c` are
   detached by definition (`isDetached()` in `src/model/index.ts`) and are drawn
   hollow. Detached ≠ missing: it means "do not join to the national line".
4. **Never interpolate a gap.** Absent cell = no published figure.
5. **`Source.label` is verbatim publisher + headline, never translated.**
   `Source.what` is bilingual. (Both live in Dataset.)

- 6. **All user-visible strings are `Bi`.** No hardcoded text in DOM/TS code; no
     one-language additions. French is authored, not translated from English.

7. **No new dependencies.** `chart.js` and `htm` (~600 B gzip) are the only
   runtime dependencies. Anything else: ask via issue first.
8. **`NoteRef` is a reference, not copy.** Metric-cell wording lives in
   `src/data/notes.ts`; chart-series and act/sitting notes live in
   `src/copy/{en,fr}/chart.ts`; cost notes in `src/copy/{en,fr}/costs.ts`. All
   rendered per locale.
9. **A figure is edited in `Dataset`, never here.** See the section above.
10. **A cost record carries three stages, never two.** `contingent` exists so
    that a statutory maximum is not recorded as money owed. Never add
    `committed` to `disbursed`, never add a `loan` row to a `spending` total,
    never sum a `perPerson` maximum. Render an empty cell as "not published",
    never as 0.
11. **The illegal-act register is not a series.** `ILLEGAL_ACTS` is a list of
    cases. No daily aggregate, no conviction rate, no sum of `count` across
    records — a count of records is not a count of crimes, and a rate over the
    records that reached court is a survivorship artefact.

- 12. **`CHARGE_LABELS` is total.** It is `Record<ChargeId, Bi>`; never widen it
      to `Partial`, and never add a fallback string to paper over a missing id. A
      type error there means the Dataset pin and the labels disagree.
- 13. **A note never restates a status or a count.** Both are fields. A note
      says who published the figure, when, what was derived from what, and what the
      source does not say.
- 14. **An ICD-10 code or an AIS ordinal is a codebook entry, not a diagnosis.**
      `CODE_SPANS` states what a published label _could_ stand for and carries
      `assignment: "none"` throughout. Never render a code as a patient's, never
      compute ISS/NISS/TRISS from it, and never attach a per-injury figure to a
      span whose `grain` is `"severity"` — 52 of the register's 79 are exactly
      that, and they have no injury type to price.

## Task recipes

**Change a 2026 figure** — do it in `Dataset`: `src/data/facts.ts` there
(`Obs` = `{ low, high, q? }`, point figure ⇒ `low === high`), plus a `Source`,
plus `npm run typecheck` and `npm run check:casualties` in that repo. Here the
only follow-up is the pin bump (`git submodule update --remote vendor/dataset`)
plus a rebuild. If a cell needs a new explanation, the wording is
`src/data/notes.ts` in **this** repo, attached via `noteRef`.

**Change a historical series** — same: `Dataset`, `src/data/episodes/<movement>.ts`,
one `Row` per week (`w` sequential, `from`/`to` ISO). Never edit the shim.

**Add a note** — `src/data/notes.ts` here; referenced by `noteRef` from the
Dataset cell; must exist in both languages.

**Add an act or sitting note** — `src/copy/{en,fr}/chart.ts`, under `actNotes`,
keyed by the exact record id from `Dataset` (`act-…` or `sit-…`). Both locales,
or the missing one renders `actNoteMissing`. The note explains provenance and
procedure — who published it, when, that a date is derived and from what, what
the source does not say, which step the case reached. It never restates the
status (printed from `status`) or the count (printed from `count` or its
`refs`). The record itself is edited in `Dataset`, never here: `src/data/illegal/`
is a shim.

**Add or fix a charge label** — `src/copy/legal.ts`, in `CHARGE_LABELS`, both
locales. The map is `Record<ChargeId, Bi>`, so a new id from `Dataset` does not
compile until the label exists, and a label for an id that no longer exists is
also a type error. A label names the offence; it never states a verdict.

**Add an injury classification** — the codebook is **not** here: add the
`CodeSpan` in `Dataset:src/data/casualties/coding.ts`, add the `NativeLabel` id
it keys on, then bump the pin. Rendering is local: the labels for `grain`, the
nine AIS regions and the two "no code" / "no AIS" strings live in
`src/sections/casualties/copy.en.ts` and `copy.fr.ts`, typed by
`CasualtyCopy` in `src/copy/types.ts`, so a new `AisRegion` or a new `Grain`
member is a type error there until both locales name it. `codingTable()` in
`src/sections/casualties/tables.ts` builds the table with `html`; a cell that
carries a code is a `string`, never markup. Then `npm run build` and stage
`docs/bundle.js` and `docs/styles.css`.

**Add a cost note** — the id is `CostNoteRef` in Dataset's `src/data/costs.ts`;
the wording goes in **both** `src/copy/{en,fr}/costs.ts` under `notes`, keyed by
that exact string. `costNoteText()` warns once and renders '' for a miss, so a
typo is silent on the page — check both locales by hand. Do not add a `NoteRef`
kind: a cost row has no date-metric cell to hang off.

**Add a page** — add a `PageId` + `PageSpec` in `src/site/routes.ts`; create the
HTML shell in `docs/` with the right `data-page` and relative links
(`relHref()`); add a mount branch in `src/entry/main.ts`; add a section module;
`npm run build`. `docs/styles.css` and `docs/bundle.js` are shared — no per-page
assets.

**Change wording** — edit `src/copy/{en,fr}/…` (both) or the section's
`copy.en.ts`/`copy.fr.ts`; never a literal in a chart or DOM call. Markup
strings in a section are structure, not copy: a French sentence inside an
htm template is a bug, not a translation.

**Fix a chart** — check `src/charts/specs.ts` and `datasets.ts` first: most
"missing chart" or "wrong range" bugs are spec/dataset wiring, not the drawing
engine. Detached styling comes from `src/core/colors.ts` (`hollow`).

**Add a `NoteRef` kind** — the type is in `src/model/index.ts` (this repo), the
resolution branch is in `src/charts/notes.ts`, and the wording is wherever the
strings live (see invariant 8). The switch ends in `default: return ""`, so a
missing branch fails silently: add the case, the copy for both locales, and the
header paragraph in `notes.ts` that enumerates the kinds.

## Known traps

- `docs/bundle.js` is minified in production builds; do not read it to
  understand behaviour — read `src/`.
- `npm run build` emits no sourcemaps; the committed `docs/*.map` files cannot
  be regenerated without a `--watch` build. Treat maps as local-only.
- `src/entry/main.ts` mounts are individually guarded — a section that never
  renders usually means the page's `data-page` value or the `PAGES` entry is
  wrong, not that the mount failed.
- A failed import from `src/data/…` almost always means `vendor/dataset` is not
  checked out, not that a file was deleted.
- Do not reformat `src/data/notes.ts` or the Dataset data files: they carry
  hand-written verification comments (`FIX n`, arithmetic cross-checks) that are
  part of the record.
- **A type error naming a `ChargeId` is a submodule problem until proven
  otherwise.** `src/copy/types.ts` re-exports the Dataset package, so the union
  is whatever `vendor/dataset` is pinned at. Run `git submodule status` before
  touching `CHARGE_LABELS`.
- **`actNotes` wins over nothing.** `noteText()` returns
  `m.actNotes[ref.id] ?? m.actNoteMissing` — a stale key is not an error, it is
  a record id that changed in `Dataset` and a note that now describes nothing.
  If a note stops appearing, diff the record ids before editing the prose.
- **The illegal-act register has no page.** The data and both locales of every
  label exist; nothing mounts them. Do not invent a chart for it: a daily count
  of records counts press coverage.
- **A code in the casualty table is a string, not a link.** `CODE_SPANS.icd10`
  holds category labels (`S05.7`, `T14.0`), not entities to resolve. Build every
  cell through `html` interpolation so it becomes a text node — never
  `innerHTML`, and never a template that half-builds a `<tr>`.
- **`CODE_SPANS` is a codebook, so a wrong code is a wrong claim about the
  data, not a styling bug.** If a span's `ais` range and its rung's `mais`
  disagree, `check:casualties` in `Dataset` is where it fails, not here.

## Definition of done

`npm run typecheck` passes · `npm run lint` passes · `npm run build` ran ·
`docs/bundle.js` and `docs/styles.css` staged · no `.map` staged · both locales
updated · every new figure has a verbatim-labelled source **in `Dataset`** · no
range collapsed, no gap interpolated, no flag relaxed · no shim edited by hand ·
any new `actNotes` key present in both locales · any new `ChargeId` labelled in
both locales and no `CHARGE_LABELS` widened to `Partial` · no note restating a
status or a count · any new `AisRegion` or `Grain` member labelled in both
`casualties/copy.{en,fr}.ts` · no ICD-10 code rendered as a diagnosis and no
ISS/NISS computed from a span · PR body states which figures changed and where
in `Dataset` they changed. · every cost note id exists in both
`src/copy/en/costs.ts` and `src/copy/fr/costs.ts` · no `committed` figure added
to a `disbursed` one
